The problem

Every AI hiring tool eventually asks a model to read too much.

The naive version of AI screening is simple: paste the whole job description and the whole resume into a prompt, ask for a match score. It works fine for five candidates. At fifty, the model starts drowning good signal in generic language — "collaborative team player," "fast-paced environment" — that shows up in every profile whether or not the person can actually do the job.

Sift's answer

Narrow the field cheaply first, with semantic retrieval, then spend the expensive, explainable scoring step only on candidates worth reading closely. It's the same two-stage shape production recruiting platforms use once they're operating at real scale — just built small enough to fit in a portfolio project.

How it works

What happens when a candidate moves through Sift

Five stages, each doing one job. Retrieval and scoring are deliberately separate steps — not because it looks more sophisticated, but because they're solving different problems.

Describe the role

A hiring manager types a rough idea. An LLM call turns it into a structured job post, plus a short list of the skills that actually matter for retrieval later — kept separate from the marketing language around them.

Embed the pool

Every candidate profile is converted into a vector with a local embedding model. No data leaves the machine for this step, and there's no per-candidate API cost.

Retrieve, don't guess RAG

The role's key skills are embedded too. Cosine similarity narrows the candidate pool down to the profiles semantically closest to the role — before any expensive model call happens.

Score with reasons

Only the retrieved candidates reach the LLM. Each one gets a 0–100 score and a plain-language explanation of what matched and what's missing — not just a number to trust blindly.

Brief the interviewer

Pick any scored candidate and get a generated briefing: strengths, gaps worth probing, and three interview questions tailored to that specific profile.

What it does

Three tools, one pipeline

Job description generator

Turns a one-line idea into a structured post — plus a distilled skills list that later powers retrieval, kept separate from the surrounding prose.

RAG-filtered scoring

Semantic retrieval shortlists the pool before scoring. Every score ships with a sentence of reasoning — no unexplained numbers.

Interview prep briefing

Strengths, gaps to probe, and three targeted questions — generated per candidate, ready before the interviewer walks in.

What's real, what's simulated

Portfolio scope, stated plainly instead of hidden.

Actually working

  • Live AI job description + skills generation
  • Real semantic retrieval over embedded candidate profiles
  • Explainable AI scoring, not a black-box number
  • Generated, per-candidate interview briefings

Simulated for this scope

  • Candidate pool is synthetic, AI-generated data — not sourced
  • No calendar sync or interview scheduling
  • No live voice interview pipeline
  • Vector store is in-memory — resets on restart
